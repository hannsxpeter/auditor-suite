# I18N: Internationalization and Localization Readiness

Weight 8. Active when an i18n runtime, a message catalog, or an RTL or multi-locale requirement exists.
Owns: whether the implementation can be localized correctly: strings in the catalog, messages built without concatenation, plural rules, locale-aware dates, numbers, and currency, direction and language taken from the locale, and layouts that survive longer text.
Not here: physical CSS properties (STYLE-R4); a root `<html lang>` that is missing entirely (SEM-R4); the wording and tone of the copy (uxauditor).
Standards: ECMA-402 (the `Intl` API), ICU MessageFormat, Unicode CLDR plural rules, WCAG 3.1.1 and 3.1.2.
Read first: the i18n setup (config, provider, locale detection), one message catalog, and the load-bearing screens.

## Cards

### I18N-R1 User-facing strings hardcoded outside the catalog
- Leads: `scan.sh I18N-R1` lists capitalized text between tags and hardcoded `placeholder`, `title`, `alt`, and `aria-label` values.
- Confirm: visible text, button labels, error messages, or attribute text (`alt`, `aria-label`, `placeholder`, `title`) are literals in the components of a project that ships a message catalog.
- Not a finding if: the string is not user-facing (a log line, a test id, a class name); the surface is documented as single-locale (an internal admin).
- Severity: High when a shipped non-default locale shows untranslated text on load-bearing flows; Medium otherwise.
- Fix: move the string into the catalog and render it with the project's translate function, attribute text included.
- Verify the fix: in a second locale, the view shows no source-language text.
- Refs: WCAG 3.1.2; the i18n library's docs

### I18N-R2 Messages built by concatenation or hand-written plurals
- Leads: `scan.sh I18N-R2` lists string concatenation around variables and `count === 1 ?` plural checks.
- Confirm: a sentence is assembled from pieces (`"You have " + n + " items"`, or template literals that mix catalog keys and literals), so translators cannot reorder the words; plurals are chosen with `n === 1` or a helper that knows only one and other (wrong for Arabic, Polish, Russian, and others).
- Not a finding if: the pieces are separate UI elements, not one sentence.
- Severity: High for load-bearing messages in a shipped locale with complex plurals; Medium otherwise.
- Fix: one catalog message with placeholders and ICU plural syntax (`{count, plural, one {# item} other {# items}}`), or `Intl.PluralRules`.
- Verify the fix: the catalog has one key per sentence with placeholders; each plural key covers the locale's plural forms.
- Refs: ICU MessageFormat; Unicode CLDR plural rules; ECMA-402 `Intl.PluralRules`

### I18N-R3 Dates, numbers, or currency formatted by hand or with a fixed locale
- Leads: `scan.sh I18N-R3` lists `toFixed`, hardcoded locale arguments, date-pattern strings, and currency symbols joined to numbers.
- Confirm: prices, dates, or numbers are formatted with `toFixed(2)` plus a symbol, a hardcoded locale (`toLocaleString('en-US')`), or a fixed pattern (`MM/DD/YYYY`), instead of `Intl.NumberFormat`, `Intl.DateTimeFormat`, or `Intl.RelativeTimeFormat` with the active locale.
- Not a finding if: the value is machine-readable output (an ISO date in an API call or a `datetime` attribute).
- Severity: High when prices or dates on load-bearing flows show the wrong format for a shipped locale (a decimal comma read as a thousands separator); Medium otherwise.
- Fix: `new Intl.NumberFormat(locale, { style: 'currency', currency })` and `new Intl.DateTimeFormat(locale, options)` with the active locale.
- Verify the fix: switching the locale changes the separators, the currency position, and the date order.
- Refs: ECMA-402

### I18N-R4 Direction and language not taken from the locale
- Leads: `scan.sh I18N-R4` lists `dir` and `lang` attributes and code that sets them.
- Confirm: an RTL locale ships but `dir="rtl"` is never set, or is fixed to `ltr`; the root `lang` stays fixed while the locale changes; language-switched fragments (a language picker that lists native names) have no `lang`; directional icons (arrows, chevrons, progress) do not mirror in RTL.
- Not a finding if: every shipped locale is left-to-right and `lang` follows the locale.
- Severity: High when an RTL locale renders left-to-right; Medium when `lang` does not follow the locale (screen readers speak with the wrong voice).
- Fix: set `lang` and `dir` on the root from the active locale on every change; add `lang` to foreign-language fragments; mirror directional icons under `[dir="rtl"]`.
- Verify the fix: switching to an RTL locale sets `dir="rtl"` on the root and mirrors the layout.
- Refs: WCAG 3.1.1, 3.1.2; HTML `dir` attribute

### I18N-R5 Layouts that break with longer or different text
- Leads: `scan.sh I18N-R5` lists fixed widths, truncation, and `nowrap` on text elements.
- Confirm: buttons, tabs, labels, or menus have fixed widths, or `white-space: nowrap` with truncation, that clip longer translations (German and Finnish often run 30 percent longer); text is baked into images.
- Not a finding if: the element grows with its content or wraps.
- Severity: Medium when load-bearing buttons or labels clip in a shipped long-text locale; Low otherwise.
- Fix: size text containers by their content (`min-width`, padding, wrapping); move text out of images.
- Verify the fix: pseudo-localize the catalog (longer strings with accents): no text clips on the load-bearing views.
- Refs: W3C Internationalization "Text size in translation"

## Also check
- Hardcoded `alt`, `aria-label`, and `title` text in translated screens (file under I18N-R1; the missing name itself is A11Y).
- Locale detection that ignores the user's saved choice and falls back to the browser language on every visit.

## Paper controls (look protective, protect nothing)
- A translation library installed while half the screens hardcode source-language text.
- A locale switcher that changes strings but never `dir`, `lang`, or number formatting.
- A plural helper that handles only one and many.
