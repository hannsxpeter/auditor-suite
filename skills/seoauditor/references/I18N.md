# I18N: Internationalization and hreflang

Weight 5. Active when more than one locale, language, or region exists. Floor dimension.
Owns: hreflang (reciprocity, self-reference, codes, x-default, targets), canonicals across languages, locale redirects by IP or Accept-Language, locale coverage and consistency, and html lang and og:locale per locale.
Not here: canonicals within one language (CANON); html lang on single-language sites (SOCIAL-R6); the base sitemap (CRAWL-R6).
Standards: Google Search Central (tell Google about localized versions of your page; locale-adaptive pages; managing multi-regional and multilingual sites), ISO 639-1, ISO 3166-1 alpha-2, BCP 47.
Read first: the i18n config (locales list, default locale), locale routing and middleware, the hreflang generator (head or sitemap), and one localized page per locale.

If only one locale exists, mark I18N not applicable and do not recommend hreflang.

## Cards

### I18N-R1 Localized pages canonicalize to another language (quick)
- Leads: `scan.sh I18N-R1` lists canonicals that mention a locale or the default language, and the default-locale setting.
- Confirm: localized pages set their canonical to the default-language URL (or to one constant), so Google treats them as duplicates and ignores the hreflang cluster.
- Not a finding if: each localized page canonicalizes to itself.
- Severity: Critical when every localized page does it, because the other locales drop out of the index; High for one section.
- Fix: make each locale's canonical its own URL, and list the alternates with hreflang.
- Verify the fix: the served canonical of `/de/preise` is `https://<host>/de/preise`.
- Refs: Google Search Central (localized versions)

### I18N-R2 hreflang is not reciprocal or leaves out the page itself
- Leads: `scan.sh I18N-R2` lists hreflang emitters in head code and sitemaps.
- Confirm: page A lists page B but B does not list A, or pages leave out their own locale, usually because each page hand-writes its alternates or only some templates emit them.
- Not a finding if: one generator builds the full cluster from one locales list for every page (read it).
- Severity: High, because Google ignores hreflang links without return links.
- Fix: generate hreflang centrally from the locales list for every localized route, including a self entry.
- Verify the fix: for two locales of one page, each served page lists every locale, itself included.
- Refs: Google Search Central (localized versions)

### I18N-R3 hreflang codes are invalid
- Leads: `scan.sh I18N-R3` lists locale strings such as `en_US`, `en-UK`, and region-only codes.
- Confirm: codes use underscores (`en_US`), invalid regions (`en-UK` instead of `en-GB`, or `en-EU`), region-only values (`US`), or internal app locale names copied into hreflang without mapping.
- Not a finding if: a mapping function converts internal locales to ISO codes before output.
- Severity: High when the main locales are invalid (Google ignores them); Medium for one locale.
- Fix: map locales to an ISO 639-1 language plus an optional ISO 3166-1 alpha-2 region (`en-GB`, `pt-BR`).
- Verify the fix: every hreflang value in the built HTML matches `xx` or `xx-YY`, or is `x-default`.
- Refs: ISO 639-1, ISO 3166-1, Google Search Central (localized versions)

### I18N-R4 Visitors are redirected by IP address or Accept-Language
- Leads: `scan.sh I18N-R4` lists Accept-Language reads, geo headers, and locale detection settings.
- Confirm: middleware or server code redirects by IP country or `Accept-Language` with no way to reach the other locales, so Googlebot, which crawls mostly from US addresses without a language header, sees one locale only.
- Not a finding if: detection only suggests a locale (a banner or selector) and every locale URL serves its own content to everyone.
- Severity: High.
- Fix: serve each locale at its own URL to everyone and offer a dismissable suggestion instead of a redirect; point `x-default` at a selector page if needed.
- Verify the fix: `curl -sI -H 'Accept-Language: de' https://<host>/en/` answers 200, not a redirect.
- Refs: Google Search Central (locale-adaptive pages)

### I18N-R5 hreflang targets are not indexable, or x-default is missing
- Leads: `scan.sh I18N-R5` lists x-default entries.
- Confirm: hreflang points at URLs that redirect, 404, are noindexed, canonicalize elsewhere, differ in trailing slash, or are relative; or no `x-default` exists for the fallback or selector page, or it points at a page that is not neutral.
- Not a finding if: the targets come from the same route table as the canonicals and are absolute.
- Severity: Medium.
- Fix: build hreflang targets from the absolute canonical URLs and add `x-default`.
- Verify the fix: every hreflang URL in the built HTML answers 200 and canonicalizes to itself.
- Refs: Google Search Central (localized versions)

### I18N-R6 Locale coverage and signals are inconsistent
- Leads: `scan.sh I18N-R6` lists locales lists, `<html lang>`, og:locale values, and `xmlns:xhtml` declarations.
- Confirm: hreflang exists only on the home page; the routing locales list differs from the hreflang or sitemap generator's list; `<html lang>` or `og:locale` does not match the route's locale; regional pages are untranslated copies; a sitemap uses `xhtml:link` without declaring `xmlns:xhtml`.
- Not a finding if: every list comes from one config and templates read the route's locale.
- Severity: Medium; High when most localized pages lack hreflang.
- Fix: drive routing, hreflang, sitemap alternates, `lang`, and `og:locale` from one locales config.
- Verify the fix: a localized page serves matching `lang`, `og:locale`, and hreflang for its locale.
- Refs: Google Search Central (managing multi-regional and multilingual sites)

## Also check
- Subdirectories (`/de/`) are the simplest URL strategy; mixing ccTLDs, subdomains, and `?lang=` parameters complicates every signal.

## Paper controls (look protective, protect nothing)
- hreflang with no return links (I18N-R2).
- hreflang pointing at noindexed or redirected URLs (I18N-R5).
- A cross-language canonical that voids hreflang (I18N-R1).
- An IP-based auto-redirect (I18N-R4).
- hreflang on the home page only (I18N-R6).
- hreflang treated as an AI Overviews lever: it picks which URL is shown, not what is retrieved for an answer.
